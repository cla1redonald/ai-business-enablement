# The where-to-start kit

This is everything that guides sequencing, gathered into one named bundle. It covers the
part of a diagnostic where the client's top opportunities are picked, and it runs
straight out of the kit as a facilitated session pack. The client keeps it, and can
repeat it every quarter and at every reorganisation.

## The two decisions (before any work)

**Decision A.** Name one accountable owner for the enabler programme. A named executive
protects that person's time, and also protects learning time for the stretched teams. It
costs little, and it is the cheapest test of whether the organisation means to move.

**Decision B.** Confirm whether the work serves growth or cost. If it is growth-led, the
first portfolio points at the commercial streams. If it is cost-led, it points at
internal reporting and the work of assembling things by copy and paste. The two readings
pick different starting sets from the same discovery, so this choice has to come before
the starting set does.

## The wave rule

A wave is a group of moves that wait on nothing outside the group, so wave one can start
on the day the decision is made. Wave one typically holds the review gate and
verification pattern, scoping the connectors, the cheapest data connections and the
measurement moves. Wave two is typically the identity and permission rollout. Wave three
builds on both, with the data platform, agent hosting and more review capacity.

Never run an enabler on its own. An enabler only pays back when a business outcome is
delivered across it, and the design details only come out when there is a real case to
work on. So every wave pairs groundwork with a win people can see.

## The quick-win rule

The quick win is the stream with the most quantified evidence that waits on nothing.
Shape it as a bounded test. If there is a tool trial already under way on that stream,
bring it to a decision as part of the test. Run the test on capability that has passed
the verification pattern, so that it proves an enabler at the same time. If the owning
team is under pressure, reshape the test so it costs them almost nothing. Asking what
the client needs to protect is part of sequencing.

## The gating counts

An opportunity is gated when it waits on at least one enabling gap, and open when it
waits on none. A gated opportunity is no less valuable than an open one. Its route
simply starts with the gate. Prefer gate moves that release many opportunities. The
count of opportunities waiting on each gap is what turns the diagnosis into a sequence.

## The six questions (the choosing session)

Taken in order, these questions get a leadership team from the full discovery to a
starting set it can defend, in one working session, by choosing among routes. The
enablers are not up for choice. They go ahead in wave order regardless, and their gaps
come in only as the gates that decide whether a route is open.

1. **Where does unstarted value concentrate?** Rank the functions by weighted mass, then
   ask each owning team what is genuinely already moving.
2. **Is the path open or gated?** Open routes can start now. A gated route is not worth
   less. Its first step is the gate.
3. **If it is gated, what does moving the gate release?** Prefer gates that release many
   opportunities.
4. **How strong is the evidence underneath?** Deep evidence supports a commitment. Thin
   evidence supports a verification step before anything is built.
5. **What does it cost to try?** Grade the effort route by route and use it to order the
   starting set. Use effort to set the order, never to judge what a route is worth. A
   hard route at the top of the discovery still outranks an easy one at the bottom.
6. **What does the route assume, and who owns testing that?** State the assumption, name
   an owner, and test it before funding the work.

Each question maps to a column in the workbook, so the session runs on the client's own
data. The mapping is in the report's annex E and in the workbook's Read me, and both are
generated from one source. Before the session, the owning teams confirm again what is
already moving, because the evidence describes a stated period and no delivery statuses
are recorded. A session usually produces one gate move, a few starts on open routes
where untouched value concentrates, and one measurement move so that results can be
proven. Run it again every quarter, at any change of structure or budget, and whenever
an enabling gap closes.

## The don'ts

1. **Do not build a weighted composite score** to rank the opportunities. The weights
   would be invented rather than evidenced, and the argument moves from the work to the
   scoring formula. This is the one executives remember, so say it early.
2. **Do not plan or grade effort for a whole stream at once.** A single grade at that
   level means very little. Commit route by route.
3. **Do not ask the evidence to justify decisions about roles.** It was gathered for a
   productivity scope. It describes friction in processes and says nothing about whether
   any role is needed.
4. **Do not add new investment where work is already moving.** Confirm the statuses with
   the teams, then put the untouched mass first.
5. **Do not wait for the biggest open question to be settled before starting.** Name
   what is open now. Once the two decisions are made, wave one needs nothing more than
   the will to run it.
6. **Do not put AI output into client-facing or regulated paths** until a shared
   verification pattern and audit evidence exist. Assurance is far cheaper to build
   before scale than to retrofit afterwards.

## Reading a map

Read a value stream map by its waits and its pain rather than by its busiest steps. The
longest waits usually hold the time, and the worst pain marks the routes worth testing
first. A route is a path through the map, and routes are what the six questions choose
between.
